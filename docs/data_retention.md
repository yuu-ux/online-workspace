# データ保持期限と削除ジョブ

## 削除対象

定期処理は、実行時刻を基準に次のデータを物理削除する。

| 対象 | 保持期限 | 削除条件 |
|:--|:--|:--|
| `messages` | 3か月 | `sent_at < 実行時刻 - 3か月` |
| 退会済みユーザーの `work_sessions` | 退会から30日 | `users.deleted_at < 実行時刻 - 30日` |

「3か月を超えた」「30日を超えた」データを対象とするため、境界日時と同じデータはその回では保持し、次回以降の実行で削除する。月の計算には暦月を使用し、3か月を90日には換算しない。

## 実行頻度と設定

既定では毎日 03:00 UTC に実行する。以下の環境変数で変更できる。

| 環境変数 | 既定値 | 用途 |
|:--|:--|:--|
| `DATA_RETENTION_CHAT_HISTORY_MONTHS` | `3` | チャット履歴の保持月数 |
| `DATA_RETENTION_WITHDRAWN_WORK_HISTORY_DAYS` | `30` | 退会後の作業履歴の保持日数 |
| `DATA_RETENTION_CLEANUP_CRON` | `0 0 3 * * *` | Spring cron形式の実行時刻 |
| `DATA_RETENTION_ZONE` | `UTC` | cronを評価するタイムゾーン |
| `DATA_RETENTION_SCHEDULING_ENABLED` | `true` | 定期実行の有効・無効 |
| `DATA_RETENTION_RUN_ONCE` | `false` | 起動時に1回だけ追加実行するか |

削除件数と実行時刻はアプリケーションログに記録する。複数インスタンスで同時に実行されても、対象データの物理削除は冪等であり、削除済みデータを再作成しない。

## 失敗時の再実行

チャット履歴と作業履歴の削除は同一トランザクションで実行する。途中で失敗した場合は全削除をロールバックし、次回の定期実行で同じ対象を再処理する。

定期実行を待たずに再実行する場合は、対象環境で次の設定を付けてアプリケーションを起動する。

```shell
DATA_RETENTION_SCHEDULING_ENABLED=false \
DATA_RETENTION_RUN_ONCE=true \
./gradlew bootRun
```

`Data retention cleanup completed` ログと削除件数を確認したらプロセスを停止する。処理は期限を超えたデータだけを再検索するため、同じ実行を繰り返しても結果は変わらない。

## 監査データとの整合

認証・認可の重要操作やアクセス記録、`reports`、`admin_actions`、および退会の事実を表す `users.id` / `users.deleted_at` はこのジョブの削除対象に含めない。これにより、要件で求められる監査記録と通報対応履歴を保持する。

退会ユーザーのプロフィールや認証情報の匿名化・削除は退会処理側の責務とし、このジョブは要件で保持期限が明示されているチャット履歴と作業履歴だけを処理する。
