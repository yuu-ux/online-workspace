## 1. 目的

本アプリは、**家で作業が捗らない人や、誰かと一緒に作業したい人向けに、オンラインで一緒に作業できる場を提供する**ことを目的とする。

### 1.1 既存アプリとの違い

既存のオンライン作業スペースはフレンドになることを前提に作られてるため、誰でもいいから一緒に作業がしたいというニーズを見たせてないと感じる。
そのため、本アプリでは誰でも参加できるようなルームを作成できるようにしたい。誰でも参加できるようなルームを作成するにあたって荒しや誹謗中傷, 詐欺等のリスクも高まることが懸念されるため、ブロック機能や通報機能でコミュニティの健全性は担保できるようにしたい。

## 5. 機能要件

### 5.1 フレンド機能

- ユーザーは他ユーザーをフレンド登録できる
- フレンド登録は申請・承認フローを設けず、操作時に即時追加する
- フレンドの中でお気に入り登録できる
- ユーザーは登録済みフレンドを解除できる
- ユーザーはお気に入り登録済みフレンドを解除できる
- フレンド一覧を表示できる

### 5.2 ルーム設定

- ルーム作成時にルームカテゴリを設定できる
    - カテゴリは運営側が事前に用意した候補から選択できる形式とする
- ルーム作成時にルームの説明文を設定できる
- ルーム作成時に作業スタイルを設定できる
    - 例: 黙って集中 / 雑談OK
- ルーム作成時に人数上限を設定できる（2人以上12人以下）
- ルーム作成時に公開範囲を選択できる（公開 / 招待されたメンバーのみ / フレンドのみ）
- 公開ルーム: 誰でも参加可能
- フレンド限定ルーム: 作成者のフレンドのみ参加可能
- 招待制ルーム: 招待されたユーザーのみ参加可能
    - 招待制ルームでは招待リンクを発行できる
    - 招待リンクの有効期限はデフォルトで1時間とする
    - ルームが閉じられたタイミングで招待リンクは無効化する
    - ユーザーが手動で招待リンクを無効化する機能は一旦提供しない
    - 招待リンクを知ってれば誰でも入室できる

### 5.3 音声通話機能

- 同一ルーム内で複数人の音声通話ができる
- 1ルームあたり同時通話人数は最大12人
- ユーザーがルームに入室したタイミングで、自動的に音声通話へ参加する
- ユーザーは自分のマイクをミュート / ミュート解除できる
- 通信切断や再接続時は、自動的に同じルームの音声通話へ復帰する
- 音声通話の実現方式として WebRTC を想定する
    - 実現可否および構成詳細は要検討とする

### 5.4 タイマー機能

- ユーザーがルームに入室したタイミングで、作業時間の自動計測を開始する
- ユーザーがルームから退出したタイミングで、作業時間の自動計測を停止する
- 自動計測した作業時間はユーザー単位で作業履歴に記録される
- 任意でポモドーロテクニック（25分作業 + 5分休憩を1セットとする時間管理手法）等の手動タイマー機能を利用できる（余力対応）

### 5.5 作業履歴

- カテゴリごとに累計作業時間を閲覧できる
- 累計作業時間を閲覧できる
- 日付単位で、ルーム / 参加ユーザ / 作業内容 / 作業時間 などを閲覧することができる
    - 作業内容: ルーム作成時に設定したカテゴリを利用する
    - 作業時間: ルーム作成時刻でなく、ユーザーの参加時刻と終了時刻を表示

### 5.6 通報・ブロック

- ユーザーは他ユーザーをブロックできる
    - ブロック時は、ブロックした相手/された相手のプロフィール・検索表示を相互に禁止する
    - ブロック関係にあるユーザー間では、招待・フレンド申請・メッセージ等の接触行為を不可にする
    - ブロック関係にあるユーザー間では、新たに同一ルームへ参加することを禁止する
    - ブロック成立時点ですでに同一ルームに参加している場合、そのルーム利用は継続できる
    - ブロック関係にあるユーザーが同一ルームの状態から退出した後は、再度同一ルームで接触できない
- ユーザーは不適切行為を通報できる
    - 通報対象はユーザー単位とする
    - 通報時は理由を選択できる（例: ハラスメント / 誹謗中傷 / スパム / 詐欺・なりすまし / 不適切コンテンツ / その他）
    - 通報時は任意で詳細説明を入力できる
    - 同一ユーザーから同一対象ユーザーへの重複通報は一旦制限しない
    - 管理者は通報理由・詳細説明・対象ユーザー・通報ルーム・通報時刻を確認できる

### 5.7 運営管理機能

- 管理者専用の管理画面を提供する
- 管理者は通報一覧を確認できる
- 管理者は通報一覧に対してフィルタ機能およびソート機能を利用できる
- 通報を段階的に対処できる（警告 / 一時停止 / 永久停止）
    - 警告: ガイドライン違反の注意喚起を行う
    - 一時停止: 期間を定めてアカウント全機能を利用不可にする
    - 永久停止: アカウントを無期限で利用不可にする
    - 段階的対処は、違反内容・悪質性・再犯有無に基づいて決定する
    - 管理者の対処内容と実施日時は対応履歴として記録できる
    - 管理者対応（警告 / 一時停止 / 永久停止）の結果は対象ユーザーへメール通知できる
    - メール通知には理由、実施日時、適用期間（期限がある場合）を含める

### 5.8 システム監視機能

- Prometheusで主要メトリクスを収集し、Grafanaで可視化できる
- 500エラー発生時は、管理者へ即時通知できる
    - 即時通知の通知先としてDiscord連携を検討
- ヘルスチェックエンドポイント（/actuator/health）を監視し、失敗時にアラート通知できる
- 要検討
    - 監視対象メトリクスを定義する（API応答時間、エラー率、CPU/メモリ、DB接続数、同時接続数、WebSocket接続数）
    - アラート条件を定義する（例: 5xx率、P95応答時間、CPU使用率の閾値と継続時間）
    - メトリクスおよびログの保持期間を定義する
    - 監視ダッシュボードの必須表示項目を定義する

### 5.9 マイページ・プロフィール編集・退会機能

- ユーザーはマイページで自分のプロフィール情報を閲覧できる
    - 名前
    - アイコン
    - 自己紹介
    - 作業カテゴリ
    - 作業記録
        - 日毎の作業時間のグラフ
        - カテゴリ別の累積作業時間のグラフ
- ユーザーはプロフィール情報を編集できる
- プロフィールアイコンをタップするとプロフィール詳細が閲覧できる
- プロフィールの表示/非表示をユーザーが設定できる
    - プロフィールを非表示にした場合、他ユーザーには名前とアイコンのみ表示する
- ユーザー名で他ユーザーを検索できる
- 検索結果から他ユーザーのプロフィールを閲覧できる
- ユーザーはマイページから退会手続きを開始できる
- 退会時は確認メッセージを表示し、誤操作を防止する
- 退会完了後は当該アカウントでログインできない

### 5.10 プライバシーポリシー / 利用規約

- ユーザーが閲覧可能なプライバシーポリシー画面を提供する
- ユーザーが閲覧可能な利用規約画面を提供する

## 8. セキュリティ要件

### 8.1 公開ページ要件

- プライバシーポリシー画面および利用規約画面は、公開ページとして誰でも閲覧できる

### 8.2 認証・認可

- 8.1 の公開ページを除くすべての機能は、ログイン前提でアクセス制御を行う
- ルームの公開範囲（公開 / 招待のみ / フレンドのみ）に応じて参加可否を判定する

### 8.3 アカウント保護

- パスワードは平文保存せず、bcryptでハッシュ化して保存する
- ログイン失敗の連続試行に対してレート制限(5回)を行う
- セッション管理を行い、ログアウト時にログインセッションを無効化する

### 8.4 通信・データ保護

- 通信はHTTPS および WSS を前提とする
- 個人情報（プロフィール情報、通報情報等々）は適切なアクセス制御下で保存・参照する
- 攻撃対策のため、認証・認可に関する重要操作やアクセス記録を保持する

### 8.5 脆弱性対策

- SQLインジェクション対策を実施する（プレースホルダ利用を前提）
- XSS対策としてユーザー入力の表示時エスケープを行う
- CSRF対策を実施する

### 8.6 運用セキュリティ

- 監視基盤（Prometheus / Grafana）で異常を検知した場合、運用時に追跡可能とする
